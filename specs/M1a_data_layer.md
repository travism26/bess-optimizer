# ADW Feature Spec: M1a, Data Layer

- **Repo:** bess-optimizer
- **Master spec:** specs/M1_python_core.md (frozen interfaces and canonical schema live there; on any conflict the master wins)
- **Depends on:** scaffold only (models.py). Independent of M1b.
- **Implements:** src/bess/data/prices.py, the `bess fetch` CLI command, tests/test_data.py, tests/fixtures/

## Objective

Fetch ERCOT day-ahead hourly settlement point prices via gridstatus, normalize
them to the canonical schema, cache to parquet, validate hard, and commit a
frozen fixture that every downstream feature tests against without network
access.

## In scope

1. `fetch_da_prices(location, start, end, cache_dir) -> pd.DataFrame` exactly as
   signed in the master spec. Reads from parquet cache when present, fetches and
   writes cache when not.
2. Canonicalization to the master spec schema: interval_start_utc,
   interval_end_utc, iso, market, location, location_type, price. All timestamps
   converted to UTC immediately on ingest.
3. Validation on every return path: sorted strictly increasing per location,
   deduplicated, no gaps. A gap raises with the missing intervals listed.
   Never interpolate silently.
4. `bess fetch` typer command wrapping the function (locations, start, end,
   cache dir from config.toml defaults, overridable by flags).
5. Frozen fixture: one month, HB_NORTH, July 2023 (744 hourly rows), committed
   as tests/fixtures/hb_north_2023_07.parquet. Generated once via the real
   fetch, then never regenerated by CI.
6. tests/test_data.py.

## Out of scope

Optimizer, backtest, plots, `bess backtest` and `bess plot` commands, any ISO
other than ERCOT, any market other than DAY_AHEAD_HOURLY.

## Acceptance criteria

1. Returned DataFrame matches the canonical schema exactly: column names,
   dtypes, tz-aware UTC timestamps.
2. Spring DST day (2023-03-12) yields 23 hourly rows and fall DST day
   (2023-11-05) yields 25, with interval_start_utc continuous hourly across
   both. Test this from a small committed raw-format sample, not the network.
3. Duplicate rows in raw input are dropped; out-of-order input is sorted.
4. A synthetic input with a missing hour raises, and the exception message
   contains the missing interval timestamp.
5. Negative prices pass through unmodified. No clipping, no filtering, no NaN
   coercion of negatives.
6. All gridstatus imports and calls are confined to data/prices.py. Nothing
   else in src/ imports gridstatus. Version pinned in pyproject.toml.
7. No test touches the network. The one live-fetch test is marked (e.g.
   pytest.mark.manual) and excluded from the default run and CI.
8. Fixture file exists, is under 100 KB, loads, and passes validation.

## Gotchas

1. ERCOT publishes in prevailing Central Time. Convert to UTC at the ingest
   boundary and never assume 24 rows per calendar day anywhere.
2. gridstatus API surface moves between versions. Pin it, isolate it, and keep
   the canonicalization logic separate from the fetch call so an upstream
   change is a one-function fix.

## Definition of done

All 8 criteria green in CI, ruff and mypy clean, fixture committed, `bess fetch`
works against the live API when run manually.
